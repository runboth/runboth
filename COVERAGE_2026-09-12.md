# Coverage and abstention report, 2026-09-12

*Every number here was computed by a script reading the JSON records that `runboth adjudicate --json`
emitted, never transcribed from prose. Method: each repository at HEAD against 30 commits
back, budget 80, prune OFF, so every `no_change` below was reached by executing the function
in both trees. Windows 11, Python 3.11, one machine. Repositories are shallow clones taken
2026-09-12, so the commit windows differ from the August table and the function counts are
not comparable line for line; the ADJUDICATED PERCENT is.*

## Why this document exists

The gap register says the honest alternative to a headline coverage number is a published
coverage-and-abstention report per real repository, so a buyer can see the exact percentage
adjudicated on code shaped like theirs before trusting a verdict. This is that report. It also
records what the number looked like at three points in one day, because the jumps are the
story and a jump that is not explained should be suspected.

Jinja is measured once, in the final run only, because it is the slow one (682 seconds) and
carrying it through three iterations would have bought nothing: **1,147 functions, 1,038
no_change, 7 changed, 102 abstained, 91% adjudicated.**

**The headline figure: 4,026 functions across eight repositories, 91% adjudicated, 367
abstentions each with a reason, ZERO tracebacks.** It would read 94% with click at its
pre-tempdir-fix number, and 91% is the one to quote, because the extra three points came from
functions that were failing fast on a sandbox artifact rather than being checked.

"Before the day's fixes" is itself after the first hour: the true starting state crashed on
flask in 37 seconds and produced no table at all (see `CLAUDE.md`, 2026-09-12 section, item 1).

**What moved the numbers, and why each is a fix rather than a laundering:**

- **requests 45 to 98, attrs 39 to 76:** the sandbox had replaced `subprocess.Popen` with a
  function, so `asyncio` failed to IMPORT on Windows, so every test module that imported
  hypothesis abstained as "import failed". Those functions were never executed before and are
  executed now. Nothing was reclassified; the import succeeds.
- **attrs 76 to 98:** the method-comparison path passed only the tree root, not the `src/`
  root, so every method in a test class imported the INSTALLED attrs from site-packages and
  failed on version skew. The three worker calls now receive the package roots.
- **flask 97 to 95:** down two points, and correct. More test-class methods now import and
  execute, and some block or start servers, so they hit the 30-second wall clock and abstain
  honestly instead of abstaining on a bogus import.
- **click 93 to 61, and this one cost coverage rather than buying honesty.** Fixing the temp
  directory means click's `CliRunner` and `isolated_filesystem` actually work, so 123 functions
  now do real filesystem and CLI work and exceed the 30-second wall clock; 103 of them are in
  test files, the rest in `core.py`. **I expected these to be old FALSE `no_change` verdicts
  and checked instead of assuming, and the check said no:** running
  `src/click/core.py::Argument.make_metavar` through the worker with the defect on and off
  returns byte-identical keys (`['val', "'X'"]`) both ways, fast, so its old verdict was
  genuine. So click's 93% was not inflated in the way I first wrote, and this drop is a
  **tuning problem, not a retraction**: the wall clock is too low for test-heavy code that
  touches the filesystem. Two clean runs read 61% and 65%, which is also four points of
  run-to-run variance sitting on that boundary. Raising the clock per repo is the open work,
  and it is tracked as known work.
- **flask witnesses 17 to 13:** the object-state channel now records the delta a call made
  to `self`, not the full snapshots, so a constructor that gained an attribute no longer makes
  every method on its class `changed`. Four constructor-blamed witnesses disappeared. The
  remaining 13 sit in files that genuinely changed across the window (`ctx.py` was
  substantially rewritten; `blueprints.py` gained decorator-without-parentheses support).

## What the remaining abstentions are made of (final run)

367 abstentions across 4,026 functions:

| category | count | what it means |
|---|---|---|
| wall clock | 179 | the function ran past 30 seconds. **click accounts for 123 and httpx for 39**, both test suites that start CLI runners or servers. The largest category, and the most tunable |
| object construction | 91 | the class could not be built from mined or generated arguments. The last STRUCTURAL gap: jinja 34, flask 16, attrs 16, toolz 10 |
| import | 60 | the module's own import fails in a bare environment. **55 are jinja test modules needing `trio`**, a genuinely absent optional dependency, which is an honest abstention and not a tool defect |
| nondeterministic | 26 | the before version disagreed with itself across processes; comparing it would be meaningless. 19 are click |
| class resolution | 6 | nested classes (`Outer.Inner.method`) are not resolved yet |
| sandbox output / error | 4 | the worker died without usable output |
| keyword-only ctor | 1 | a constructor requiring keyword-only arguments, which the positional sandbox boundary refuses |

Every one of these is a verdict with a reason. **Zero tracebacks across 4,026 functions in
eight repositories**, on the first day this code ran on Windows against fresh clones.

Read as a buyer would: on ordinary library code the tool adjudicates 96 to 98 percent
(requests, attrs, markupsafe, toolz), on large template and web frameworks 91 to 95 percent
(jinja, flask), and on test suites that drive CLI runners and servers it falls to 61 to 86
percent because those functions genuinely take longer than the budget allows. The gap is
concentrated and named, which is the point of publishing it.

**The finding that matters more than the coverage number.** Chasing those 15 click import
abstentions surfaced a defect CLASS that can make the tool lie rather than merely give up.
`runboth/control_overblock.py` demonstrates it on a constructed case: two functions that genuinely differ
(`len(root) + n` against `len(root) + n + 1`, both calling `tempfile.gettempdir()` first, the
way click's `CliRunner` does) come back **`no_change` under the over-blocking sandbox** and
`changed` with a witness under the fixed one. Both versions raise inside `gettempdir()` before
reaching the difference, so the keys compare equal. That is a false same, the one error this
project says it cannot afford, and it was produced by this project's own hardening.

**Scope of that claim, stated precisely.** The false-same is demonstrated on a constructed
case; it is NOT established that any specific real verdict in the August tables was false. The
one real function checked (`Argument.make_metavar`) was genuine. What the constructed case
proves is that the class is reachable, which is enough to justify the three paired controls now
in `sandbox.run_controls` (read a temp dir path, subclass Popen, import asyncio), each watched
to FAIL with its fix disabled via `RUNBOTH_CONTROL_NO_TEMPDIR_PRERESOLVE`.

**An eighth defect, found by reading this table.** Click's 15 import abstentions were all
`FileNotFoundError: No usable temporary directory found`. `tempfile.gettempdir()` probes
candidate directories by CREATING a file in each, and the sandbox blocks writes before the
module under test is imported, so any module calling `gettempdir()` at import time failed to
import and the reason blamed the repository. Fixed by resolving the temp directory once,
before the write guard is installed, which caches `tempfile.tempdir` so later calls do not
probe. Writing into it is still blocked and the sandbox control still passes. This is the same
shape as the Popen defect: **the sandbox's own hardening was breaking imports, and the reason
string said so for a month.**

## The headline measurement, re-run the same day

An agent asked to refactor real functions, DeepSeek `deepseek-chat`, budget 150, toolz, 40 targets:

    refactors adjudicated                  36
    behaviour PRESERVED                    20
    behaviour CHANGED despite the claim    16     44%   (Wilson 95%: roughly 29 to 60)
    excluded: model returned it unchanged   2
    excluded: model output unusable         1
    excluded: tool abstained                1

By witness shape: 3 value-became-exception or the reverse; 5 exception type only; 7 where a
lazy iterator became eager or the reverse (the same computation, errors surfacing at a
different time); 1 other. Every witness is in `results/agent_refactor_audit_2026-09-12.json`.

This is inside the 19 to 35% that Dristi and Dwyer published in February 2026 (arXiv
2602.15761), at the top of it, on a frontier model. It is a replication, not a first, and
should be cited as one.

## What this report does NOT say

- Coverage is on Python at function level. Rust and JavaScript are test-outcome granularity.
- `sampled(80)` is evidence, never proof. The residual class (tie-breaks, exact thresholds) is
  real; the mined-constant sweep shrinks it and nothing removes it.
- The commit-study control (7 flagged, 54 quiet, 7 misses, 13 libraries) is only PARTIALLY
  re-run since the object-state channel changed to deltas: 16 of 68 pairs (toolz 12,
  markupsafe 4) came back 15 quiet, 1 found that the tests missed, **zero false alarms**. The
  other 52 pairs and 11 libraries are stale.
- **The ledger's deep path costs about 3 seconds per function per commit** (markupsafe, 78
  units, 7m15s for 2 commits). The fast `--exec pyfunc` path does 3 commits in 1.8s but sees
  only top-level functions of arity 3 or less. Any demo that backfills a prospect's repo live
  must use pyfunc and say so.
- The sandbox contains accidents, not attackers. These repositories were trusted.
- The largest repository here is jinja. Nothing has touched a monorepo.
